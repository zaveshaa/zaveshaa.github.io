# zaveshaa.github.io

<https://zaveshaa.github.io/>

Plain static files. No build step, no dependencies, no framework.

| File | What it is |
| --- | --- |
| `index.html` | Landing page |
| `blog.html` | Notes index — regenerate with `tools/build_blog.py` |
| `portfolio.html` | CV, with contribution data pulled from the GitHub API |
| `notes/*.html` | One file per note |
| `feed.xml` | RSS, also generated by the build script |
| `tools/build_blog.py` | Rebuilds `blog.html` and `feed.xml` from `notes/` |

## Writing a note

A note is one HTML file in `notes/`. Nothing styles it, so any font, CSS,
image or layout works — the page is only ever what you wrote in it.

1. `cp notes/_template.html notes/my-note.html`
2. edit the copy, then set the comment block at the top:

   ```html
   <!--
     title:   My note
     date:    2026-09-29
     summary: One line for the index.
     status:  draft
   -->
   ```

3. `python3 tools/build_blog.py`
4. commit both the note and the regenerated `blog.html` / `feed.xml`

Notes listed in `PLANNED` at the top of the build script keep their slot in the
index even before the file exists — they show as dashed cards rather than dead
links. A file that is not in `PLANNED` still shows up, appended at the end.
Underscore-prefixed files are ignored, which is how `_template.html` stays out
of the index. `status: draft` keeps a post out of the feed without hiding it.

GitHub Pages builds this site with Jekyll, which ignores any file or directory
whose name starts with `_` or `.`. So a note called `_draft-thing.html` will
appear on the index but never be published — keep note slugs to letters, digits
and dashes. The upshot is that `_template.html` is a working file in the repo
and is never served publicly, which is what you want from scaffolding.

## Local preview

```sh
python3 -m http.server 8000
# then open http://localhost:8000/
```

Serving over HTTP matters for the portfolio: it fetches contribution data from
the GitHub API, which browsers refuse to do from `file://`.

## Portfolio numbers

The metrics in `portfolio.html` are a dated snapshot used when the GitHub API
is unreachable, and are refreshed from the live API when the page loads. When
you update them by hand, update the snapshot date in the note under the
metrics and in the two failure messages in the script.
